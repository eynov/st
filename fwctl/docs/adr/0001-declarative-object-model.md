# ADR 0001：声明式对象模型取代 forwards[]

- 状态：Accepted
- 日期：2026-07-31

## 背景

旧版本的状态用一个扁平数组表达端口转发：

```json
{"sport":"29312","dport":"29312","dip":"192.0.2.20","proto":"tcp","dest_port":"29312"}
```

每条记录内联保存目标地址。同一台落地机被转发 10 个端口，IP 就在文件里出现 10
次；`both` 协议还会把一次逻辑操作拆成两条记录。后果是：改一个 IP 要改 N 处、
无法给规则命名、无法单独禁用一条规则、无法统计单条规则的流量、删除时只能按
数组下标操作。

## 决策

用三层对象模型替代 `forwards[]`：

```text
Target        Service
      ↘      ↙
        Rule
```

- **Target**：命名地址对象（一个或多个 IPv4 / CIDR）。
- **Service**：命名端口 + 协议对象。
- **Rule**：引用 Target 与 Service，自身不保存地址与端口。

对象图**严格单向**：Target 与 Service 永不互相引用，也不引用 Rule；Rule 是唯一的
绑定者。这一点在 schema 校验中实际断言，不只是文档约定。

### 身份

三类对象都有不可变 `id`（`<kind>-` + 12 位小写十六进制）和可读 `name`。

- `id` 是程序标识，创建时生成一次，此后**永不重算**——重命名、改地址、改
  description 都不触发重算。
- `name` 面向用户，在各自类型内唯一，可自由重命名。
- 规则始终按 `id` 引用，因此重命名不破坏任何引用。
- CLI、doctor、stats 和日志优先显示 `name`，仅在需要消歧时附带 `id`。

`id` 由内容哈希派生而非随机生成，长度取 12 位十六进制（48 bit）以留出足够的碰撞
余量；碰撞时向哈希输入追加 `#<n>` 重算。

### Target 是可变实体，Service 是不可变值对象

这是本 ADR 最容易被误读的一条，两者的传播行为不同，且都是刻意的。

**Target 是实体。** 身份是 `id`，地址是它的可变属性。改地址会传播到全部引用它的
规则——**这正是引入 Target 的全部意义**：换落地机 IP 只需要改一处。

Target 的地址**不要求跨 Target 唯一**。同一个地址可以属于多个 Target，用来表达
不同用途的逻辑目标、不同生命周期或所有者、同一主机上的不同业务，以及迁移期新旧
对象并存。地址集合完全相同的多个 Target 由 validate 与 doctor 输出 WARN 提醒，
schema 层不拒绝。

**Service 是值对象。** `(protocol, ports)` 构成它的值，创建后冻结；`name` 与
`description` 是可变的显示元数据。因为值不可变，全局复用不存在隐式爆炸半径。

**Service 没有 `enabled` 字段。** 一个 Service 可能被多条互不相关的规则引用，如果
它可以被禁用，禁用动作就会隐式影响所有引用方——这正是值对象要避免的情况。启用
状态属于 Rule；「停掉某条转发」的正确表达是禁用那条 Rule。

改变 Service 的值 = 新建对象 + 显式重写引用。`fw service edit --ports/--protocol`
必须携带 `--refs <规则列表>` 或 `--all-refs`，在同一事务内新建 Service 并只重写
指定的引用；缺少这两个选项时以退出码 2 拒绝，并列出当前全部引用方，让用户先看清
爆炸半径。旧 Service 失去全部引用后仍保留，由 doctor 报告为孤儿。

一句话概括两者的差别：**Target 的传播是功能，Service 的传播是事故。**

## 原因

- 地址集中存储让「换落地机 IP」变成一次编辑。
- 命名对象让规则可被引用、启用、禁用、统计、审计。
- `protocol=both` 只需一个 Service，对象数相对旧格式减半。
- 引用完整性可以被校验，扁平数组的字段组合不能。
- 单向对象图让删除与替换的推理保持局部：删除 Service 只需检查 Rule 的引用，值
  变更也不可能沿隐藏边传播到 Target。

## 后果

- 迁移必须把 `forwards[]` 反解成对象图，且要证明渲染结果不变。方案与验收标准
  见 [MIGRATION.md](../MIGRATION.md)。
- 任何写路径都必须在提交前做引用完整性校验和对象图方向校验，不能只做 schema
  校验。
- CLI 增加 `target`、`service`、`rule` 三组名词；其中 `service` 没有
  `enable`/`disable` 动词。`fw port` 与交互菜单保持不变，用户可以完全不接触新
  模型继续工作。
- Service 的值变更需要用户显式声明引用范围，比原地编辑多一个步骤。这是刻意的
  代价：它把一次可能影响多条规则的操作从「默默生效」变成「先看清再确认」。
