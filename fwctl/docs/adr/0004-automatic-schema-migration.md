# ADR 0004：自动 schema 迁移，且以渲染等价性为验收标准

- 状态：Accepted
- 日期：2026-07-31

## 背景

当前 schema 与旧格式完全不同。已部署的机器上存在正在生效的 `state.json`，其中
保存着用户当前依赖的放行端口、转发和封禁列表。要求用户手工改写状态文件是不可
接受的：改错一处就是线上防火墙故障。

## 决策

1. `state.json` 增加 `schema_version`。缺失即为旧格式，自动迁移；高于当前版本则
   拒绝加载，旧程序不得覆盖新程序的状态。
2. 迁移在加载路径上自动运行，不需要用户执行任何命令。
3. 只读命令在内存中迁移后继续执行，不写盘；只有写事务才把新状态落盘。
4. 迁移前自动备份，落盘走与其他写操作相同的事务，失败则保留原状态。
5. **验收标准是渲染等价性，不是字段搬运的完整性。** 保留一份旧渲染器快照，对每个
   用例断言：旧状态经旧渲染器产出的 ruleset，与旧状态经迁移再经新渲染器产出的
   ruleset，在归一化后相同。

### 确定性

迁移必须是确定性且幂等的：同一份输入反复迁移产出逐字节相同的结果，不同机器上迁移
同一状态得到相同的对象 id。

- 对象 id 由内容哈希派生，禁止 `uuidgen`、`$RANDOM`、`date +%s`。
- 时间戳取自源文件而非当前时刻。
- id 只在创建时生成，后续编辑不重算。
- 处理顺序显式固定：Target 按 IP 的 32 位数值升序；Service 按
  `(protocol, 起始端口, 结束端口)` 升序；Rule 按其在旧 `forwards[]` 中的原始下标。
- 碰撞处理显式固定：向哈希输入追加 `#<n>`（n 从 2 起递增）重算，直到不冲突。碰撞
  路径本身要有测试用例。

这让黄金文件比对成为可能——没有确定性，等价性测试只能逐字段断言，而那恰恰是本
ADR 拒绝的验收方式。

### 归一化的边界

归一化只允许消除三类已声明差异：

1. 表名变化（`sb_filter` / `sb_nat` → `fwctl`）；
2. counter 与 comment 的增加；
3. 空 set 的占位元素 `127.0.0.2` 与 `65535`。

第 3 项是本次唯一刻意的渲染差异：这两个值是旧实现用来绕过「空 set 无法表达」的
占位，不是用户策略。新实现使用合法空 set，占位元素随之消失。等价性测试直接忽略
它们，而不是要求逐字节一致，也不提供兼容开关。

其余任何差异都判定为迁移缺陷。

## 原因

- 自动迁移是「升级即可用」的唯一实现方式。
- 只读命令不写盘，避免巡检、监控或误用触发状态变更。
- 确定性迁移让黄金文件比对成为可能，也让同一状态在多台机器上迁移结果一致。
- 字段级断言只能证明搬运没漏，不能证明防火墙行为没变。真正要保护的是后者。

## 后果

- 仓库需要**永久保留**迁移回归固件：旧渲染器快照
  （`tests/fixtures/render-v3.sh`）与旧格式状态样本
  （`tests/fixtures/state-v1-*.json`）。今后任何渲染改动都必须继续通过
  `旧状态 → 迁移 → 新状态 → 渲染 → 归一化 → 比对` 这条链路。
- 迁移代码不能使用随机数或当前时间。
- 空 set 占位元素的消失必须在迁移文档和测试中显式声明，不能作为「归一化容忍范围」
  被默默吞掉。
- 不提供自动降级。降级路径是恢复迁移前备份并运行旧渲染器，文档中给出步骤。
